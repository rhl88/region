# CmsPro-中国行政区划-使用指南

> 版本：1.15.0 | 更新日期：2026-11-08
> 应用版本：1.7.0 | 应用 ID：cmspro.region

---

## 一、环境要求

| 项目 | 要求 |
|------|------|
| 系统 | CmsPro v5.0.0+ |
| PHP | >= 8.3 |
| 数据库 | MySQL |
| 网络 | 导入数据需访问民政部 API（`https://dmfw.mca.gov.cn`） |
| 依赖应用 | 无（开发模式下的「更新坐标」需要百度前端 AK：可在 3.13「应用设置」中配置，或复用「地图」应用的浏览器端 AK；其坐标系转换依赖「地图」应用） |

---

## 二、安装

1. 通过 CmsPro 后台「应用市场」安装中国行政区划应用，或手动将应用包上传安装。
2. 安装过程中自动创建数据库表（`app_cmspro_region_region` 和 `app_cmspro_region_closure`）。
3. **注意：安装后数据表为空，需进入后台「行政区划 → 数据管理」页面导入数据**——该页检测到无数据时会提示走 3.11「在线同步官方数据」或 3.10「导入快照包」；离线环境再使用 3.7「旧版数据更新 → 一键导入」（该面板仅 `APP_DEV_MODE=true` 开发模式可见）。

> 卸载应用会回滚业务数据表。

---

## 三、功能验证

### 3.1 后台验证

后台入口前缀 `/admin/cmspro/region`（中间件 `web + auth:admin`）：

| 菜单 | 路径 | 验证点 |
|------|------|--------|
| 数据管理 | `/admin/cmspro/region` | 数据导入/更新、街道分步导入、缓存清除、数据对比更新、地理位置导入 |
| 数据演示 | `/admin/cmspro/region/demo` | 区划选择器演示、地址位置信息展示、数据状态检查与导入引导 |

**数据管理页区划详情**：列表支持按层级、名称/代码筛选搜索，**双击任意一行**弹出该区划的完整详细信息——层级路径（省 > 市 > 区/县 > 街道/乡镇 > 村/社区，当前节点高亮）、ID、区划代码、区划名称、层级、上级区划（名称 + 代码）、上级 ID、直接子级数量、状态、经纬度（GCJ-02，保留 6 位小数，无坐标显示「暂无坐标」）、创建时间、更新时间。详情复用列表行已返回的全部字段，仅额外请求既有的 `GET /path`（层级路径）与 `GET /children`（子级数量；村/社区为最末级不请求）两个接口，不新增后端接口；任一请求失败不阻断弹层，对应位置显示占位提示。

**前台公开访问（无需登录）**：数据演示页同时开放前台地址 `/cmspro/region/demo`（中间件仅 `web`），并在 manifest `home_menus` 中注册官网导航菜单「区划演示」（`code=home_cmspro_region_demo`、`path=/cmspro/region/demo`、`order=50`）。前台菜单由框架在**应用升级**时写入 `admin_menus`（`terminal_type=home`），因此升级到 v1.6.2 后需在后台「应用管理」执行一次升级，官网导航才会出现该菜单；升级不覆盖已修改的 `sort`/`status`/`visible`。

前台模式为只读，与后台的差异：

- 接口切换到公开只读 API `/api/cmspro/region/{provinces,children,path,list}`，未注册任何写操作（导入、在线同步、快照导入/导出、坐标更新等仍仅限后台 `auth:admin`，前台请求返回 404）；
- `list` 接口分页参数受保护（`page ≥ 1`、`limit` 限定 1~200），避免被构造超大 `limit` 拉取全量数据；
- 隐藏「数据导入引导」卡片与后台链接，空态文案改为「请联系站点管理员导入区划数据」。

### 3.2 导入三级数据

安装完成后，在后台「行政区划 → 数据管理」页面中，推荐点击「**一键导入**」按钮（使用本地数据包自动完成三级区划、街道数据、地理位置全量导入，无需联网）；也可点击「导入三级数据」单项按钮（或「一键导入」悬停菜单中的「导入三级数据」项）仅导入省/市/区县数据。由于三级数据有 3200+ 条（含港澳台），系统采用**按省份分步导入**策略：

1. 前端获取省份列表（34 个）。
2. 逐个省份通过 AJAX 请求导入，每次请求处理一个省份。
3. 进度条实时显示导入进度，日志记录每个省份的导入结果。
4. 每个省份独立请求，即使服务器配置较低也不会超时。

### 3.3 启用街道级数据（可选）

如需使用街道/乡镇四级数据，在 CmsPro 后台「系统设置 → 区划设置」中开启「启用街道级数据」选项。开启后在后台页面点击「导入街道数据」按钮，系统按省份/区县分步导入（约 4 万+ 条），支持本地缓存文件 `Data/code/{区县代码}.json`。

### 3.4 导入地理位置数据（可选）

如需使用城市和区县的经纬度信息，在后台页面点击「导入地理位置」按钮。数据来源为本地 Excel 文件 `Data/地理位置编码.xlsx`，按省份分步导入。

### 3.5 在线更新坐标（GeoJSON，可选）

本地 Excel 数据源较旧（如 2023-24 新设区伊美区、湾沚区等无坐标），可在后台页面点击「在线更新坐标(GeoJSON)」按钮，从**阿里 DataV 地理数据源**（`geo.datav.aliyun.com`，免费、免 key）按省份在线拉取最新坐标并更新库中记录：

1. 前端获取库中省级列表，逐省请求导入接口。
2. 每省先更新省级自身坐标，再遍历下级市级/区县级坐标（直辖市区县、港澳区级直接取自省级文件）。
3. **名称兜底匹配**：DataV 部分编码沿用旧版（如繁昌区 DataV 340211 vs 库中 340212），编码未命中时自动在同省范围内按名称匹配，避免编码差异导致漏更新。
4. 每省返回更新/坐标相同跳过/未匹配/异常四项统计，前端逐省展示日志。

> 覆盖说明：实测省级+市级+区县级覆盖率约 3166/3213；剩余为 2023-24 最新设市县（米林市、错那市、和康县、和安县、新星市、白杨市、草湖市 7 条）DataV 暂未收录，无法通过该方式获取。坐标为 GCJ-02 坐标系，与高德地图瓦片一致。

### 3.6 数据演示

后台「行政区划 → 数据演示」页面提供区划选择器和地址位置信息的可视化演示：

1. **数据状态总览**：页面顶部以紧凑横排卡片展示三级区划数据、街道乡镇/村社区数据、地理位置数据的导入状态（图标 + 标题 + 数量同行显示，随页面宽度自适应三列等分）。街道卡片同时展示两类条数（如「38598 条街道 / 542428 条村社区」），未导入村级数据时仅显示街道条数。
2. **导入引导**：未导入对应数据时（仅后台模式显示），页面按缺失项给出引导卡片与跳转按钮，统一指向数据管理页的「**在线同步官方数据**」（推荐，可按级别同步）与「**导入快照包**」（其他站点分享的 ZIP，五级全量）两个入口——三级数据卡片给双按钮；街道卡片说明需把同步级别选为「街道」级（4 级）或「村/社区」级（5 级）；地理位置卡片说明坐标随同步包/快照包一并落库、同步后仍无坐标时再单独导入。三级数据缺失时选择器位置的空态文案同样指向这两个入口。
3. **区划选择器**：三级数据已导入时，提供省/市/区县（+街道/乡镇、+村/社区）级联选择器，最多五级，选择后显示完整路径。村/社区（level=5）挂在街道下，**复用 `GET children?code={街道编码}` 接口**按 `parent_id` 取子级，未新增接口；村级下拉仅在街道数据与村级数据都已导入时显示（后端 `$hasVillage` 开关），任一级上级变更时下级下拉自动复位为占位项。
4. **地址位置信息**：地理位置数据已导入时，选中区划后展示区划代码、名称、完整路径、经纬度信息。**村级数据当前不含经纬度**，选中村/社区时经纬度显示「无坐标数据」，地图仅清除中心点标记与边界、保留底图（不定位）。
5. **地图定位演示**：选中区划含经纬度坐标时，在地图上自动定位该区划位置并标记弹窗；任一级选中即触发（直辖市在省级选区县时同样生效）。地图组件依赖 CDN，加载失败时显示降级提示，不影响页面其他功能。
   - **底图渲染分支**：由 3.13「应用设置（地图配置）」决定。**未配置厂商地图时（默认）**沿用 Leaflet + 高德瓦片底图；**已配置时**改用所选厂商官方 JS API（百度 `BMapGL` / 高德 `AMap` 2.0 / 腾讯 `TMap` GL）渲染底图、中心点标记与行政边界，三家适配器统一暴露 `init/showPoint/clearPoint/drawRings/clearBoundary/fitAll/resize` 接口，业务函数名与调用点保持不变。
   - **坐标系**：库中坐标统一为 GCJ-02，百度底图需 BD-09，前端在传参前用 `gcj02ToBd09` 转换（腾讯/高德无需转换）；阿里 DataV 边界数据本身即 GCJ-02，同样按厂商转换后绘制。
   - **降级链**：SDK 加载失败（200ms 轮询、15s 超时、`onerror`）或初始化异常时自动回退 Leaflet + 高德瓦片并补绘当前区划边界，页面提示一次，不中断其他功能。
6. **行政区划边界**：选中省/市/区县后，地图在中心点标记之外额外绘制该区划的行政边界（浅蓝填充 `#80d8ff` + 深蓝描边 `#0091ea`），并自适应缩放到边界范围。边界数据取自**阿里 DataV GeoJSON**（`geo.datav.aliyun.com/areas_v3/bound/{code}.json`，GCJ-02 坐标系，与高德瓦片一致；浏览器端直连、免 key）。**前端请求必须以 `referrerPolicy: 'no-referrer'` 发起**：DataV 有防盗链，带外站 Referer 的浏览器请求一律返回 **403**（服务端直连不带 Referer，故后端「在线更新坐标」不受影响）。降级规则：街道/乡镇与村/社区级无官方边界数据（DataV 仅收录到区县级，街道 9 位、村级 12 位编码请求均无数据），DataV 未收录的区划（如新设区县）或请求失败时，均自动退回「仅中心点标记」，不影响页面其他功能，同时在浏览器控制台打印 `[区划边界]` 警告便于排查。
7. **左右分栏与地图常驻**：区划选择器演示区采用左右布局——左侧为级联选择与地址位置信息（按容器 26% 比例占宽，限定 360~420px，宽屏时把更多空间让给地图），右侧为定位地图并占满剩余宽度；地图**常驻显示**，页面打开即渲染中国全境底图（未选择区划时右栏不再空白），高度取「左栏高度」与 520px 的较大值，两栏底边对齐不留空白。切换级联或所选区划无坐标时只清除中心点标记与边界、保留底图；地图 CDN 加载失败时隐藏地图区并显示降级提示。窄屏 ≤992px 时自动上下堆叠，地图回落为固定 340px 高。页面整体宽度随容器自适应，不再限制最大宽度。

> 三级区划数据是演示的基础，未导入时选择器不显示；街道、村/社区与地理位置数据为可选项，未导入时对应功能不展示（村/社区下拉依赖街道数据存在），并提示导入引导。

> **显示级别约束**：选择器渲染深度还受 3.13「应用设置 → 区划级别设置」控制——各级下拉需同时满足「库中有该级数据」与「设置级别 ≥ 该级」才渲染；设置级别低于 3（区县）时降级为省 / 市两级下拉，数据状态卡片仍按库中真实数据量显示（不误报「未导入」），并在卡片下方注明当前设置级别与「前往调整」入口（前台公开模式不显示该链接）。该设置不影响对外 API 返回结果。

> **已知限制（村级级联）**：① 级联按「父子关系」逐级下钻、不按 level 编号定位下拉，而直辖市（北京/上海/天津/重庆）库中无 level=2 节点、区县直接挂省级，故直辖市路径下街道会出现在第 3 个下拉、村/社区出现在第 4 个下拉，第 5 个下拉始终为空；普通省份五级与五个下拉一一对应。② `children`/`path` 结果带 24 小时缓存，**新导入村级数据后须在数据管理页点击「清除缓存」**，否则此前查询过的街道仍会命中旧的空子级缓存（实测：清缓存前 `children?code=110101001` 返回 `data: []`，清缓存后返回 10 条村级）。

### 3.7 旧版数据更新（一键导入 / 一键数据更新）

> 提示：新装站点或数据陈旧时**推荐优先使用 3.11「在线同步官方数据」**（分钟级完成，五级全量实测约 13 分钟）；本节为旧版本地/在线导入链路，收纳在工具栏「旧版数据更新」下拉中，作为无版本服务时的兜底手段。

后台「行政区划 → 数据管理」页面工具栏（**仅 `APP_DEV_MODE=true` 开发模式显示**，位于「更新坐标」按钮右侧）提供「**旧版数据更新**」下拉按钮（点击展开面板），面板按顺序收纳四个功能按钮——「**一键导入**」（蓝色，使用应用内置本地数据包从零导入全量数据，**无需联网**）、「**一键数据更新**」（绿色，从在线源增量更新旧数据）、「清除缓存」、「更新数据」。其中「一键导入」与「一键数据更新」两者链路相互独立，单击即可自动执行；**两者均保留鼠标悬停二级下拉菜单**（在展开的面板内悬停即向左弹出）：「一键导入」二级菜单收纳本地链路三个单项入口（导入三级数据 / 导入街道数据 / 导入地理位置，标题为「本地数据导入」，悬停高亮蓝色），「一键数据更新」二级菜单收纳五个单项入口（导入三级数据 / 导入街道数据 / 导入地理位置 / 更新坐标 / 补全港澳台），点击菜单项即触发对应单项功能。点击面板外任意处或选中任一功能后面板自动收起。

**一键导入（本地数据，3 阶段）**：

| 阶段 | 内容 | 数据源 | 说明 |
|------|------|--------|------|
| ① 三级区划 | 省/市/区县导入 | 本地 `Data/list.json` | 逐省分步写入，单请求秒级完成 |
| ② 街道数据 | 约 4 万+ 条街道/乡镇 | 本地 `Data/code/*.json`（无缓存则调民政部 API） | 逐区县串行导入，失败区县自动追加一轮重试，耗时最长 |
| ③ 地理位置 | 城市/区县经纬度 | 本地 `Data/地理位置编码.xlsx` | Excel 全量导入（单请求） |

**一键数据更新（在线源，4 阶段）**：

| 阶段 | 内容 | 数据源 | 说明 |
|------|------|--------|------|
| ① 三级区划 | 省/市/区县差异化更新 | 民政部 API | 逐省分步请求，单请求秒级完成，不会超时 |
| ② 港澳台补全 | 修正台湾省级脏编码、补全港澳区级 | 阿里 DataV | 失败不中止整体流程（非关键路径） |
| ③ 街道数据 | 约 4 万+ 条街道/乡镇 | 民政部 API（本地缓存优先） | 逐区县串行导入，失败区县自动追加一轮重试，耗时最长 |
| ④ 最新坐标 | 省/市/区县经纬度更新 | 阿里 DataV GeoJSON | 逐省串行更新 |

交互说明：

1. 点击按钮弹出确认框（确认文案按「一键导入（本地数据）/ 一键数据更新（全在线源）」区分），展示各自阶段流程与耗时提示；确认后自动按顺序执行。
2. 统一进度面板显示当前阶段（步骤标签高亮，本地导入模式隐藏「最新坐标」标签）、整体进度条与实时日志；进度条按阶段分段映射（0~5% / 5~30% / 30~85% / 85~99%）；执行中标题与日志按入口按钮与链路模式区分显示。
3. 面板内「一键导入」「一键数据更新」两项的悬停二级下拉菜单提供单项导入入口（导入菜单 3 项、更新菜单 5 项），与一键导入/一键更新共用同一套互斥机制：任一任务（含一键导入、一键更新或单项导入）执行期间，两个一键按钮与菜单项同步禁用，防止并发冲突；执行中不可关闭进度面板。
4. 「一键导入」全程使用本地数据包无需联网；「一键数据更新」需联网；街道阶段数据量大（约 1 小时），执行期间请勿关闭或刷新页面。

> 适用场景：**新装应用或数据陈旧时优先使用 3.11「在线同步官方数据」（分钟级全量替换，五级全量实测约 13 分钟）**；无版本服务可用或需离线操作时，再展开「旧版数据更新」下拉——离线环境点击「一键导入」基于应用内置 `Data/` 目录官方数据包从零拉起全量数据，已安装应用且数据为旧版本时点击「一键数据更新」从在线源增量更新。

### 3.8 API 验证

统一响应格式：`{"code": 0, "message": "success", "data": ...}`，`code = 0` 成功。

```bash
# 获取所有省份列表
curl "http://www.cmspro.com/api/admin/cmspro/region/provinces"

# 获取子级区划列表
curl "http://www.cmspro.com/api/admin/cmspro/region/children?code=110000"

# 获取完整树形数据
curl "http://www.cmspro.com/api/admin/cmspro/region/tree?max_level=3"

# 获取完整路径
curl "http://www.cmspro.com/api/admin/cmspro/region/path?code=110101"

# 获取数据统计
curl "http://www.cmspro.com/api/admin/cmspro/region/stats"
```

### 3.9 导出全量数据快照包

后台「行政区划 → 数据管理」页面提供「**导出快照包**」按钮，将库中全量区划数据（含 status=0 禁用记录、含坐标）导出为标准化 ZIP 快照包，供上传至版本服务器（Versionsvr 应用「区划数据」服务）发布，各站点区划应用在线同步——使区划数据更新与区划应用发版解耦。

**操作流程**：

1. 确认库中数据为最新（可通过「一键数据更新」先更新）。
2. 点击「导出快照包」按钮，在弹窗中填写快照版本号（留空自动生成 `YYYYMMDD001` 格式）。
3. 点击「导出」，浏览器下载 `cmspro-region-data-{版本号}.zip`（内含 `regions.json` 全量记录 + `meta.json` 版本统计）。
4. 前往版本服务器后台「版本服务 → 区划数据」上传该 ZIP 发布。

**导出包契约**（与版本服务器校验规则对齐）：

| 文件 | 内容 |
|------|------|
| `regions.json` | 全量记录数组 `[{code, name, level, parent_code, status, lon, lat}, ...]`，按 level + code 排序（父级先于子级），顶级记录 `parent_code` 为 `'0'` |
| `meta.json` | `{version, count, stats: {province, city, district, street, village}, generated_at, format}` |

> 说明：库中须已有省级（level=1）数据才可导出；导出为全量快照（含禁用记录与无坐标记录，`lon`/`lat` 为 null）；版本号仅允许字母、数字、点、下划线、连字符，最长 32 位。

**性能说明（64.8 万条实测，2026-11-08）**：导出改为**流式写出**——按 level 1→5 分遍，每层一条游标查询（命中 `idx_level_code` 复合索引按编码序输出，无 offset 深翻页、无 filesort），父级 `parent_code` 由左连父表一次取回，不再构建 64 万条 `id => code` 映射（原常驻内存约 370MB）。实测全量 648,102 条导出 **6.5 秒**（空闲）、并发负载下约 35 秒，内存峰值 **76MB**；改造前同数据按 `chunk()` 深翻页需数分钟且内存数百 MB。

### 3.10 导入快照包（站点间分享）

后台「行政区划 → 数据管理」页面提供「**导入快照包**」按钮，与 3.9「导出快照包」配对——接收其他站点分享的 `cmspro-region-data-{版本号}.zip` 直接上传导入，**全量替换**本地区划数据，无需经过版本服务器，适合站点之间点对点分享数据集。

**操作流程**：

1. 从分享方获取快照包 ZIP（由对方站点「导出快照包」生成，或版本服务器下载的历史发布包，两者格式相同）。
2. 点击「导入快照包」按钮选择文件，确认弹窗提示「导入将全量替换本地区划数据（本地手工修改会被覆盖）」。
3. 点击「开始导入」，弹出与在线同步一致的**实时进度条弹层**（解包校验 25% → 契约校验 45% → 分层落库 48%~82% → 闭包表重建 84% → 清缓存记版本 90%~100%）。导入接口在文件上传完成后**立即返回任务令牌**，实际导入在响应发出后继续执行，页面通过 `sync-progress` 接口轮询（800ms/次）直到成功（`done`）或失败（`error`）；执行期间请勿关闭或刷新页面。
4. 成功后进度弹层自动关闭并提示「导入完成：版本 …, 共 … 条」后页面自动刷新；已导入版本号取包内 `meta.json` 的 `version` 写入「已同步数据版本」配置项（包内无 meta.json 时回退记录 `snapshot-{导入时刻}`），同时把「已同步数据级别」与 3.13「区划级别设置」记为 5 级（快照包始终为五级全量导出，不做级别裁剪）。

**安全机制**（与在线同步一致，另无 SHA-256 校验——上传包无可信校验和来源，故须仅导入可信站点分享的包）：

| 防护 | 说明 |
|------|------|
| 上传校验 | 仅接受 zip 格式、最大 50MB |
| 契约前置校验 | 解包（防 Zip Slip）后按同一套契约规则校验（必填/code 唯一（≤12 位）/层级引用闭环/省级必含/上限 70 万），非法数据进事务前直接拒绝 |
| 原子切换 | 新数据写入 staging 表（`*_staging`）并分批提交，闭包表在临时表内重建完成后以一条 `RENAME TABLE` 原子切换主表与闭包表；任一步失败仅清理临时表，线上数据零影响（非 MySQL 驱动退回单事务全删重插） |

### 3.11 在线同步官方数据（推荐）

后台「行政区划 → 数据管理」页面提供「**在线同步官方数据**」按钮，从版本服务器（Versionsvr 应用「区划数据」服务）在线同步官方行政区划数据，**全量替换**本地数据——新装站点或数据陈旧的站点无需再跑「一键导入/一键数据更新」（约 1 小时），**点击一次即可完成初始化（四级数据包 1 分钟内；五级全量实测约 13 分钟，建议低峰期执行）**。

**操作流程**：

1. 点击「在线同步官方数据」按钮，系统自动检查版本服务器最新已发布数据版本；弹窗中展示当前已同步版本号（从未同步则为「未同步」）与已同步级别（`local_level`，本功能上线前同步的站点显示「未知」）。
2. 弹窗展示远端版本信息（版本号、发布时间、记录总数与五级统计、更新说明），并提供**同步数据级别单选**（3/4/5 三档，默认选中已同步级别），同时提示「同步采用全量替换：本地手工修改会被覆盖，且深于所选级别的既有数据将一并清除」。
3. 点击「开始同步」，弹出**实时进度条弹层**，按阶段推进：下载数据包（5%）→ SHA-256 校验（20%）→ 解包与契约校验（30%~45%）→ 分层批量落库（48%~82%，街道层按批次细分）→ 闭包表重建（84%）→ 清缓存记版本（90%~100%）。同步接口**立即返回任务令牌**，实际同步在响应发出后继续执行（已调用 `fastcgi_finish_request()`），页面通过 `sync-progress` 接口轮询（800ms/次）直到成功（`done`）或失败（`error`）；执行期间请勿关闭或刷新页面。
4. 成功后进度条到 100% 自动关闭，页面自动刷新，数据即为官方最新版本。

**同步级别（减轻数据库压力）**：

弹窗中的级别单选决定本次**落库的最大层级**，级别越浅落库条数与耗时越少（以版本 `20261107002` 为例）：

| 选项 | 级别 | 落库条数（参考） | 说明 |
|------|------|-----------------|------|
| 同步至「区县」级 | 3 | 约 3,239 条 | 省 34 + 市 333 + 区县 2,872 |
| 同步至「街道」级 | 4 | 约 41,956 条 | 再加街道/乡镇 38,717 |
| 同步至「村/社区」级 | 5 | 约 638,772 条 | 再加村/社区 596,814（五级全量，实测约 13 分钟） |

- 弹窗每项后显示该级别的累计条数，便于按需取舍；单选只开放 3/4/5 三档（更浅的省/市级选择器无实际意义）。
- 级别裁剪在**契约校验阶段前置完成**：深于所选级别的记录不进入编码校验集合、不写 JSONL、不落库，既省内存也省磁盘 IO。
- **全量替换语义不变**：所选级别之外的既有数据（如已同步到五级后再选三级）会被一并清除，闭包表按落库数据重建（`rebuildClosureTable()` 由库中 `max(level)` 推导深度，无需额外传参）。
- 同步成功后自动写入「已同步数据级别」（`app_cmspro_region_data_sync_level`）并**联动更新** 3.13「区划级别设置」，使演示页选择器深度与实际数据一致。
- 接口层同样校验级别：`POST /api/admin/cmspro/region/sync-region-data` 的 `max_level` 仅接受 3/4/5，非法值（含缺失时的非数字）返回 `code=1` + 中文提示，且不发起任何远端请求；缺省 `max_level` 时按五级全量同步（保持旧行为）。

**安全机制**：

| 防护 | 说明 |
|------|------|
| 完整性校验 | 下载包 SHA-256 与版本服务器声明值比对，不符拒绝且本地数据零影响 |
| 契约前置校验 | 数据结构/字段/层级引用/省级必含校验在进事务前执行，非法数据直接拒绝 |
| 原子切换 | 新数据写入 staging 表（`*_staging`）并分批提交，闭包表在临时表内重建完成后以一条 `RENAME TABLE` 原子切换主表与闭包表；任一步失败仅清理临时表，线上数据零影响（非 MySQL 驱动退回单事务全删重插） |
| 版本回退 | 版本服务器保留历史版本下载，可指定旧版本号同步回退（接口 `version` 参数） |
| 版本回退保护 | 官方最新版本**低于**本地版本时（本地为先行修正版），「检查更新」不再提示同步（`need_update=false`，弹窗直接提示「本地版本已高于官方最新版本」），`sync` 接口不带 `version` 参数时同样拒绝并提示——防止误操作用官方旧包全量回退本地新数据；**显式指定版本号的历史回退不受此限** |
| 重复保护 | 未指定版本号、本地版本与官方一致**且已同步级别不浅于本次请求级别**时跳过下载；已同步级别更浅时**不跳过**，允许在同一版本上补齐更深层级（如已同步三级后再选五级） |

**性能基准**：

- 四级数据包（sqlite 内存库实测，49334 条四级区划 + 19.3 万条闭包记录）：契约校验 0.73s + 全量替换落库 5.11s ≈ **5.84s**；生产 MySQL 环境预计 1 分钟内完成（对比旧「一键导入」链路约 1 小时）。
- 五级村级数据包（MySQL 8 实测，648,102 条区划 + 315 万条闭包记录，2026-11-08）：同步链路全程流式化（校验结果写 JSONL 中间产物、按层级分遍扫描批量落库、闭包表 `INSERT...SELECT` 逐层重建、缓存按版本号整体失效），512M 内存限制下**内存峰值 88MB**。落库改为 **staging 表 + 索引后置 + `RENAME TABLE` 原子切换**：新表写前移除二级索引、写完一次性重建，闭包表重建期临时索引 `(depth, ancestor)`，全程不再逐行维护索引。实测总耗时约 **13 分钟**（795 秒），其中闭包表 315 万行索引重建约占 5 分钟、闭包表逐层重建约 2 分钟、JSONL 分遍落库约 4 分钟、契约校验约 1 分钟——瓶颈为服务器磁盘随机写 IO，**建议低峰期执行**，执行期间请勿关闭或刷新页面。
- 异步执行：同步/导入接口在响应发出后继续执行长任务（`app()->terminating()` + `fastcgi_finish_request()`），因此总耗时即使远超 nginx `fastcgi_read_timeout`（宝塔默认 300 秒）也不会出现前端「请求超时」；任务期间互斥锁（`cmspro_region:data_task_lock`，30 分钟）阻止并发重复提交。注意：任务仍依赖 PHP-FPM 进程存活，执行期间请勿重启 PHP-FPM/Web 服务或服务器。

**版本记录**：已同步版本号写入「数据同步设置 → 已同步数据版本」配置项（`app_cmspro_region_data_sync_version`，系统自动维护），本次落库的最大级别写入「已同步数据级别」（`app_cmspro_region_data_sync_level`）。**该级别配置项缺失时（本功能上线前已同步的站点）回退取库中 `max(level)`**，避免误判为 0 级而在点击在线同步时重复全量导入 64 万条。配置组由框架在应用安装/升级时按 manifest 落库；**若站点未执行过升级导致配置组缺失，同步时会自动创建该组**（`firstOrCreate` 自愈），确保版本号一定写入、前端「本地版本」正常显示，无需用户手动升级。

### 3.12 更新区划坐标（开发模式）

仅当 `.env` 中 `APP_DEV_MODE=true` 时，数据管理页「搜索」按钮右侧才显示「**更新坐标**」入口（生产环境不渲染，接口也会拒绝执行）。弹窗提供「单个更新」与「批量自动更新」两个页签。

#### 单个更新

1. 按 省/直辖市 → 市 → 区/县 → 街道/乡镇 → 村/社区 逐级选择；任一级选中后均可作为更新目标（直辖市、省直辖县级市等层级不齐的情况会自动跳级；街道下无村级数据时第五级下拉保持禁用）。
2. 系统按选中路径组装百度正地址解析地址，规则为「省+市」与「区县及以下」之间保留一个空格，例如 `浙江省嘉兴市 秀洲区嘉北街道`；选到村/社区时村名紧接街道，例如 `浙江省嘉兴市 秀洲区嘉北街道XX社区`。
3. 选中任一级区划后，「百度请求地址」下方会实时回显该区划**当前库中的经纬度**（GCJ-02，查询 `GET /api/admin/cmspro/region/coordinate`，直连数据库不走缓存）：有坐标显示 `经度, 纬度`（绿色），无坐标显示红色「暂无经纬度」；切换级联时随之刷新，单个更新成功后立即回显最新值。
4. 点击「获取坐标并更新」，前端通过百度地图 JSAPI（`BMapGL.Geocoder.getPoint`）解析地址得到 BD-09 坐标，再调用本应用接口写库（`POST /api/admin/cmspro/region/update-coordinate`）。
5. 写库前自动将 BD-09 转换为 GCJ-02，与应用内其他坐标保持一致；执行结果会同时展示百度坐标与最终存储坐标。
6. 弹窗保留，可继续选择其他区划逐条更新；表格会自动刷新。

#### 批量自动更新

一次性补齐省/直辖市、市、区县、街道乡镇的经纬度，无需逐条选择。

1. 切换到「批量自动更新」页签，勾选需要更新的层级（默认四级全选）。
2. 「仅更新缺失坐标」默认勾选：只处理 `lon`/`lat` 为空的记录；取消勾选则对选中层级全部重新解析并覆盖。
3. 「请求频率」设置每秒请求数（QPS，取值 1~10，默认 3）：控制每秒最多发起多少条百度解析请求，数值越低越稳；任务运行中修改即时生效，未运行时修改会同步到断点任务。
4. 点击「开始更新」：前端按区划代码顺序分页拉取待更新列表（`GET /api/admin/cmspro/region/coordinate-candidates`，游标分页每页 100 条），3 并发逐条调用百度地理编码，并按 QPS 限制发起间隔（最小间隔 = 1000 / QPS 毫秒），解析结果每 20 条批量写库（`POST /api/admin/cmspro/region/update-coordinate-batch`）。
5. 进度条实时显示已处理/总数、成功、失败条数；日志区记录未解析到坐标或写库失败的条目（单条解析失败自动重试 2 次）。
6. 支持「暂停/继续」与「停止」；进度与请求频率一起保存在浏览器 localStorage，页面刷新或关闭后可点击「继续上次任务」从断点继续。断点游标仅在整页处理完成后推进，避免漏更新。
7. 完成后表格与统计卡片自动刷新。

| 层级 | 参考数据量 | 说明 |
|------|-----------|------|
| 省/直辖市 | 34 | 解析为省级行政中心点 |
| 市 | 300+ | |
| 区/县 | 3000+ | |
| 街道/乡镇 | 约 4 万 | 数据量大，需保持页面打开 |

> 批量更新受百度地图 JSAPI 并发与配额限制，街道级全量补齐可能持续数小时，建议先跑省/市/区县，再单独跑街道，或按需只勾选缺失层级。仅补缺失模式下已完成记录不会重复消耗配额。出现频繁失败或限流时，可把请求频率降到 1~2 次/秒。
>
> AK 优先取 3.13「应用设置」中**本应用生效的百度前端 AK**（生效厂商为百度时）；未配置时回退到「地图」应用中配置的**浏览器端 AK**（`baidu_js_ak`），需在百度地图开放平台为该 AK 配置当前域名 Referer 白名单。坐标系转换复用「地图」应用的 `CoordinateConverter`，未安装「地图」应用时接口返回明确错误。
>
> **前置检测**：两处均取不到百度 AK 时，点击「更新坐标」不再静默失败，而是弹出「地图未配置」确认框，按下列顺序给出**具体缺失原因**并提供「前往应用设置」按钮（当前页跳转到 `/admin/cmspro/region/setting`，不用 `window.open` 以免被浏览器拦截后无任何反应）：① 地图配置组尚未注册（需先在「应用管理」升级到 1.6.0）；② 配置来源为「不启用」；③ 生效厂商为高德/腾讯（「更新坐标」依赖百度地址解析）；④ 已选百度但尚未填写百度 JS AK。

### 3.13 应用设置（区划级别 + 地图配置）

后台「行政区划 → 应用设置」页面（`/admin/cmspro/region/setting`，权限码 `cmspro.region.setting.manage`）用于配置**区划显示级别**与数据演示页使用的地图。**本应用不内置任何地图密钥**，密钥须由使用者自行到各厂商开放平台申请后填入。两部分共用同一张表单与保存接口（`POST /api/admin/cmspro/region/setting`），点击「保存设置」一次性提交。

#### 区划级别设置

「选择器显示级别」下拉（配置项 `app_cmspro_region_region_max_level`，取值 1~5，默认 5）决定数据演示页「区划选择器」渲染到第几级下拉：

| 级别 | 含义 | 演示页渲染的下拉 |
|------|------|-----------------|
| 1 | 省 | 仅省级 |
| 2 | 市 | 省 / 市 |
| 3 | 区县 | 省 / 市 / 区县 |
| 4 | 街道 | 省 / 市 / 区县 / 街道 |
| 5 | 村/社区（默认） | 省 / 市 / 区县 / 街道 / 村 |

- **作用范围仅演示页选择器**：不改变对外 API（`children`/`tree`/`list`/`path`）与 `RegionService` 的返回结果，不删除库中任何数据；未渲染层级的数据依然存在，其他业务系统按原样调用。
- **级别低于 3（区县）时降级渲染**：演示页只渲染省 / 市两级下拉；数据状态卡片仍按库中真实数据量显示（不会误报「未导入」），卡片下方注明「当前设置为 X 级（至 Y），区划选择器仅渲染至该级别」，并提供「前往调整」链接（前台公开模式不显示）。
- **与同步联动**：3.11「在线同步官方数据」与 3.10「导入快照包」成功后自动写入本设置（快照包为五级全量导出，固定记为 5 级），使选择器深度与实际落库数据一致，无需手动对齐。
- **入参校验**：仅接受 1~5 的整数，非法值（0 / 6 / 非数字）返回 `code=1` + 中文提示「区划显示级别必须为 1（省）至 5（村/社区）之间的整数」，且不落库；请求中不含 `region_max_level` 时（如仅保存地图配置）级别保持不变。
- **配置组自愈**：配置组 `app_cmspro_region_region_settings`（标题「区划设置」）由框架在安装 / 升级到 1.7.0 时按 manifest 落库；组缺失时保存级别会自动 `firstOrCreate` 建组，不会因未升级而写入失败。注意保存链路上地图配置先行校验，**从 1.5.0 及更早版本升级、尚未升到 1.6.0 的站点**仍须先升级（见下方前置条件）。

#### 地图配置

> **前置条件**：配置组 `app_cmspro_region_map_settings` 由框架在安装 / 升级应用时按 `manifest.json` 写入。**从 1.5.0 及更早版本升级的站点，必须先在「应用管理」中把本应用升级到 1.6.0**，否则设置页顶部显示红色「地图配置组尚未注册」提示，点击「保存设置」也会弹出同一原因（由保存接口返回），配置无法落库。

**三种配置来源**（`map_source`）：

| 来源 | 取值 | 行为 |
|------|------|------|
| 不启用 | `none`（默认） | 数据演示页沿用 Leaflet + 高德瓦片底图，无需任何密钥 |
| 本应用独立配置 | `own` | 使用下方所选厂商与本应用填写的前端密钥 |
| 关联「地图」应用 | `maps` | 跟随 CmsproMaps 的 `provider` 与对应前端密钥，该应用改配置后本页无需重复维护；未安装 / 未配置时自动回退瓦片底图 |

**三家厂商前端密钥**（`own` 模式下按需填写，可并存，切换厂商不必重新申请）。页面**只显示所选厂商对应的密钥项**（百度 1 项、高德 2 项、腾讯 1 项），其余厂商的输入框仅隐藏不清空，提交时一并保存：

| 配置项 | 申请入口与要点 |
|--------|---------------|
| `baidu_js_ak` | lbsyun.baidu.com → 控制台 → 应用类型选「浏览器端」并开启 JavaScript GL，配置 Referer 白名单 |
| `amap_js_key` | lbs.amap.com → 控制台 → 应用类型选「Web端(JS API)」，配置域名白名单 |
| `amap_security_code` | 与高德 Key 同页的「安全密钥（securityJsCode）」；JS API 2.0 强制要求，缺失会报 `INVALID_USER_SCODE`，前端在 SDK 加载前注入 `window._AMapSecurityConfig` |
| `tencent_js_key` | lbs.qq.com → 控制台 → 创建应用 → 添加 Key（勾选 Web端 JavaScript GL），配置 Referer 白名单 |

**安全与存储**：四项密钥属敏感数据，落库前用 `Crypt::encryptString` 加密（读取时按 `eyJpdiI6` 前缀兼容系统配置页写入的历史明文），配置缓存键前缀 `cmspro_region:map_config:`、TTL 3600 秒，保存后即时失效。设置页文本框**明文回显**已配置值，输入新值即覆盖，**清空文本框并保存即删除该密钥**。`resolveEffective()` 只向前端下发 `provider/key/sdk_url/coordinate_system/security_config`，服务端密钥（如 `*_server_key`）绝不输出。

**保存链路**：设置页 `POST /api/admin/cmspro/region/setting`，控制器用 `MapSettingService::ALLOWED_KEYS` 白名单接收（禁止 `$request->all()`），来源与厂商非法时返回 `code=1` + 中文提示；成功后返回当前生效配置并刷新页面。

**验证要点**：
1. 未配置（`none`）时打开数据演示页，地图仍为 Leaflet + 高德瓦片，五级级联、中心点标记与行政边界均正常。
2. 配置为 `own` + 任一厂商密钥后刷新演示页，底图切换为该厂商官方 JS API，选中区划仍能标记定位并绘制边界（百度下坐标自动 GCJ-02 → BD-09）。
3. 配置为 `maps` 且「地图」应用未安装时，页面回退瓦片底图，设置页「关联『地图』应用」面板显示「未安装或未启用」。
4. 密钥填写错误或厂商 SDK 不可达时，演示页自动回退 Leaflet 并提示一次，不影响级联选择与数据展示。

## 六、常见问题

### Q: 安装后没有数据？

安装应用仅创建数据库表，需在后台「行政区划 → 数据管理」页面手动点击「导入三级数据」导入。

### Q: 导入数据提示超时？

三级数据采用按省份分步导入策略，每个省份独立请求，不会超时。如仍异常，请检查服务器能否访问民政部 API。

### Q: 如何启用街道/乡镇四级数据？

在 CmsPro 后台「系统设置 → 区划设置」中开启「启用街道级数据」选项，然后在数据管理页面点击「导入街道数据」。

### Q: 如何获取行政村/社区五级数据？

村级/社区级（level=5，约 59.7 万条）数据通过「在线同步官方数据」获取：版本服务器 `20261107001` 及以后版本包含村级数据（村级为 12 位编码，应用升级时自动扩容 code 字段）；`20261107002` 为村级精度修正版（52,606 条错配村级按源街道名称修正挂接、补全 119 条新补街道下 1,780 条村级，总量 638,772 条）。五级全量约 64 万条，同步耗时约 10 分钟量级（内存峰值远低于 512M 限制），建议低峰期执行。

### Q: 数据更新后前台不生效？

查询结果缓存 24 小时，数据更新时自动清除；如仍异常，可手动点击「清除缓存」。

### Q: 直辖市如何查询子级？

北京、天津、上海、重庆的区县直接挂在省级下（无中间市级），`getChildren('110000')` 直接返回区县列表。
