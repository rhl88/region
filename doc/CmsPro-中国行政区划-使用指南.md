# CmsPro-中国行政区划-使用指南

> 版本：1.11.1 | 更新日期：2026-11-07
> 应用版本：1.5.0 | 应用 ID：cmspro.region

---

## 一、环境要求

| 项目 | 要求 |
|------|------|
| 系统 | CmsPro v5.0.0+ |
| PHP | >= 8.3 |
| 数据库 | MySQL |
| 网络 | 导入数据需访问民政部 API（`https://dmfw.mca.gov.cn`） |
| 依赖应用 | 无（开发模式下的「更新坐标」依赖「地图」应用的百度浏览器端 AK） |

---

## 二、安装

1. 通过 CmsPro 后台「应用市场」安装中国行政区划应用，或手动将应用包上传安装。
2. 安装过程中自动创建数据库表（`app_cmspro_region_region` 和 `app_cmspro_region_closure`）。
3. **注意：安装后数据表为空，需进入后台「行政区划 → 数据管理」页面手动导入数据。**

> 卸载应用会回滚业务数据表。

---

## 三、功能验证

### 3.1 后台验证

后台入口前缀 `/admin/cmspro/region`（中间件 `web + auth:admin`）：

| 菜单 | 路径 | 验证点 |
|------|------|--------|
| 数据管理 | `/admin/cmspro/region` | 数据导入/更新、街道分步导入、缓存清除、数据对比更新、地理位置导入 |
| 数据演示 | `/admin/cmspro/region/demo` | 区划选择器演示、地址位置信息展示、数据状态检查与导入引导 |

### 3.2 导入三级数据

安装完成后，在后台「行政区划 → 数据管理」页面中，推荐点击「**一键导入**」按钮（使用本地数据包自动完成三级区划、街道数据、地理位置全量导入，无需联网）；也可点击「导入三级数据」单项按钮（或「一键导入」悬停菜单中的「导入三级数据」项）仅导入省/市/区县数据。由于三级数据有 3200+ 条（含港澳台），系统采用**按省份分步导入**策略：

1. 前端获取省份列表（34 个）。
2. 逐个省份通过 AJAX 请求导入，每次请求处理一个省份。
3. 进度条实时显示导入进度，日志记录每个省份的导入结果。
4. 每个省份独立请求，即使服务器配置较低也不会超时。

### 3.3 启用街道级数据（可选）

如需使用街道/乡镇四级数据，在 CmsPro 后台「系统设置 → 区划设置」中开启「启用街道级数据」选项。开启后在后台页面点击「导入街道数据」按钮，系统按省份/区县分步导入（约 4 万+ 条），支持本地缓存文件 `Data/code/{区县代码}.json`。

### 3.4 导入地理位置数据（可选）

如需使用城市和区县的经纬度信息，在后台页面点击「导入地理位置」按钮。数据来源为本地 Excel 文件 `Data/地理位置编码.xlsx`，按省份分步导入。

### 3.5 在线更新坐标（GeoJSON，可选）

本地 Excel 数据源较旧（如 2023-24 新设区伊美区、湾沚区等无坐标），可在后台页面点击「在线更新坐标(GeoJSON)」按钮，从**阿里 DataV 地理数据源**（`geo.datav.aliyun.com`，免费、免 key）按省份在线拉取最新坐标并更新库中记录：

1. 前端获取库中省级列表，逐省请求导入接口。
2. 每省先更新省级自身坐标，再遍历下级市级/区县级坐标（直辖市区县、港澳区级直接取自省级文件）。
3. **名称兜底匹配**：DataV 部分编码沿用旧版（如繁昌区 DataV 340211 vs 库中 340212），编码未命中时自动在同省范围内按名称匹配，避免编码差异导致漏更新。
4. 每省返回更新/坐标相同跳过/未匹配/异常四项统计，前端逐省展示日志。

> 覆盖说明：实测省级+市级+区县级覆盖率约 3166/3213；剩余为 2023-24 最新设市县（米林市、错那市、和康县、和安县、新星市、白杨市、草湖市 7 条）DataV 暂未收录，无法通过该方式获取。坐标为 GCJ-02 坐标系，与高德地图瓦片一致。

### 3.6 数据演示

后台「行政区划 → 数据演示」页面提供区划选择器和地址位置信息的可视化演示：

1. **数据状态总览**：页面顶部以紧凑横排卡片展示三级区划数据、街道乡镇/村社区数据、地理位置数据的导入状态（图标 + 标题 + 数量同行显示，随页面宽度自适应三列等分）。街道卡片同时展示两类条数（如「38598 条街道 / 542428 条村社区」），未导入村级数据时仅显示街道条数。
2. **导入引导**：未导入对应数据时，页面显示引导提示和跳转按钮，引导用户前往数据管理页面导入。
3. **区划选择器**：三级数据已导入时，提供省/市/区县（+街道/乡镇、+村/社区）级联选择器，最多五级，选择后显示完整路径。村/社区（level=5）挂在街道下，**复用 `GET children?code={街道编码}` 接口**按 `parent_id` 取子级，未新增接口；村级下拉仅在街道数据与村级数据都已导入时显示（后端 `$hasVillage` 开关），任一级上级变更时下级下拉自动复位为占位项。
4. **地址位置信息**：地理位置数据已导入时，选中区划后展示区划代码、名称、完整路径、经纬度信息。**村级数据当前不含经纬度**，选中村/社区时经纬度显示「无坐标数据」，地图仅清除中心点标记与边界、保留底图（不定位）。
5. **地图定位演示**：选中区划含经纬度坐标时，在 Leaflet + 高德瓦片地图上自动定位该区划位置并标记弹窗；任一级选中即触发（直辖市在省级选区县时同样生效）。地图组件依赖 CDN，加载失败时显示降级提示，不影响页面其他功能。
6. **行政区划边界**：选中省/市/区县后，地图在中心点标记之外额外绘制该区划的行政边界（浅蓝填充 `#80d8ff` + 深蓝描边 `#0091ea`），并自适应缩放到边界范围。边界数据取自**阿里 DataV GeoJSON**（`geo.datav.aliyun.com/areas_v3/bound/{code}.json`，GCJ-02 坐标系，与高德瓦片一致；浏览器端直连、免 key）。**前端请求必须以 `referrerPolicy: 'no-referrer'` 发起**：DataV 有防盗链，带外站 Referer 的浏览器请求一律返回 **403**（服务端直连不带 Referer，故后端「在线更新坐标」不受影响）。降级规则：街道/乡镇与村/社区级无官方边界数据（DataV 仅收录到区县级，街道 9 位、村级 12 位编码请求均无数据），DataV 未收录的区划（如新设区县）或请求失败时，均自动退回「仅中心点标记」，不影响页面其他功能，同时在浏览器控制台打印 `[区划边界]` 警告便于排查。
7. **左右分栏与地图常驻**：区划选择器演示区采用左右布局——左侧为级联选择与地址位置信息（按容器 26% 比例占宽，限定 360~420px，宽屏时把更多空间让给地图），右侧为定位地图并占满剩余宽度；地图**常驻显示**，页面打开即渲染中国全境底图（未选择区划时右栏不再空白），高度取「左栏高度」与 520px 的较大值，两栏底边对齐不留空白。切换级联或所选区划无坐标时只清除中心点标记与边界、保留底图；地图 CDN 加载失败时隐藏地图区并显示降级提示。窄屏 ≤992px 时自动上下堆叠，地图回落为固定 340px 高。页面整体宽度随容器自适应，不再限制最大宽度。

> 三级区划数据是演示的基础，未导入时选择器不显示；街道、村/社区与地理位置数据为可选项，未导入时对应功能不展示（村/社区下拉依赖街道数据存在），并提示导入引导。

> **已知限制（村级级联）**：① 级联按「父子关系」逐级下钻、不按 level 编号定位下拉，而直辖市（北京/上海/天津/重庆）库中无 level=2 节点、区县直接挂省级，故直辖市路径下街道会出现在第 3 个下拉、村/社区出现在第 4 个下拉，第 5 个下拉始终为空；普通省份五级与五个下拉一一对应。② `children`/`path` 结果带 24 小时缓存，**新导入村级数据后须在数据管理页点击「清除缓存」**，否则此前查询过的街道仍会命中旧的空子级缓存（实测：清缓存前 `children?code=110101001` 返回 `data: []`，清缓存后返回 10 条村级）。

### 3.7 旧版数据更新（一键导入 / 一键数据更新）

> 提示：新装站点或数据陈旧时**推荐优先使用 3.11「在线同步官方数据」**（1 分钟内完成）；本节为旧版本地/在线导入链路，收纳在工具栏「旧版数据更新」下拉中，作为无版本服务时的兜底手段。

后台「行政区划 → 数据管理」页面工具栏（**仅 `APP_DEV_MODE=true` 开发模式显示**，位于「更新坐标」按钮右侧）提供「**旧版数据更新**」下拉按钮（点击展开面板），面板按顺序收纳四个功能按钮——「**一键导入**」（蓝色，使用应用内置本地数据包从零导入全量数据，**无需联网**）、「**一键数据更新**」（绿色，从在线源增量更新旧数据）、「清除缓存」、「更新数据」。其中「一键导入」与「一键数据更新」两者链路相互独立，单击即可自动执行；**两者均保留鼠标悬停二级下拉菜单**（在展开的面板内悬停即向左弹出）：「一键导入」二级菜单收纳本地链路三个单项入口（导入三级数据 / 导入街道数据 / 导入地理位置，标题为「本地数据导入」，悬停高亮蓝色），「一键数据更新」二级菜单收纳五个单项入口（导入三级数据 / 导入街道数据 / 导入地理位置 / 更新坐标 / 补全港澳台），点击菜单项即触发对应单项功能。点击面板外任意处或选中任一功能后面板自动收起。

**一键导入（本地数据，3 阶段）**：

| 阶段 | 内容 | 数据源 | 说明 |
|------|------|--------|------|
| ① 三级区划 | 省/市/区县导入 | 本地 `Data/list.json` | 逐省分步写入，单请求秒级完成 |
| ② 街道数据 | 约 4 万+ 条街道/乡镇 | 本地 `Data/code/*.json`（无缓存则调民政部 API） | 逐区县串行导入，失败区县自动追加一轮重试，耗时最长 |
| ③ 地理位置 | 城市/区县经纬度 | 本地 `Data/地理位置编码.xlsx` | Excel 全量导入（单请求） |

**一键数据更新（在线源，4 阶段）**：

| 阶段 | 内容 | 数据源 | 说明 |
|------|------|--------|------|
| ① 三级区划 | 省/市/区县差异化更新 | 民政部 API | 逐省分步请求，单请求秒级完成，不会超时 |
| ② 港澳台补全 | 修正台湾省级脏编码、补全港澳区级 | 阿里 DataV | 失败不中止整体流程（非关键路径） |
| ③ 街道数据 | 约 4 万+ 条街道/乡镇 | 民政部 API（本地缓存优先） | 逐区县串行导入，失败区县自动追加一轮重试，耗时最长 |
| ④ 最新坐标 | 省/市/区县经纬度更新 | 阿里 DataV GeoJSON | 逐省串行更新 |

交互说明：

1. 点击按钮弹出确认框（确认文案按「一键导入（本地数据）/ 一键数据更新（全在线源）」区分），展示各自阶段流程与耗时提示；确认后自动按顺序执行。
2. 统一进度面板显示当前阶段（步骤标签高亮，本地导入模式隐藏「最新坐标」标签）、整体进度条与实时日志；进度条按阶段分段映射（0~5% / 5~30% / 30~85% / 85~99%）；执行中标题与日志按入口按钮与链路模式区分显示。
3. 面板内「一键导入」「一键数据更新」两项的悬停二级下拉菜单提供单项导入入口（导入菜单 3 项、更新菜单 5 项），与一键导入/一键更新共用同一套互斥机制：任一任务（含一键导入、一键更新或单项导入）执行期间，两个一键按钮与菜单项同步禁用，防止并发冲突；执行中不可关闭进度面板。
4. 「一键导入」全程使用本地数据包无需联网；「一键数据更新」需联网；街道阶段数据量大（约 1 小时），执行期间请勿关闭或刷新页面。

> 适用场景：**新装应用或数据陈旧时优先使用 3.11「在线同步官方数据」（1 分钟内全量替换）**；无版本服务可用或需离线操作时，再展开「旧版数据更新」下拉——离线环境点击「一键导入」基于应用内置 `Data/` 目录官方数据包从零拉起全量数据，已安装应用且数据为旧版本时点击「一键数据更新」从在线源增量更新。

### 3.8 API 验证

统一响应格式：`{"code": 0, "message": "success", "data": ...}`，`code = 0` 成功。

```bash
# 获取所有省份列表
curl "http://www.cmspro.com/api/admin/cmspro/region/provinces"

# 获取子级区划列表
curl "http://www.cmspro.com/api/admin/cmspro/region/children?code=110000"

# 获取完整树形数据
curl "http://www.cmspro.com/api/admin/cmspro/region/tree?max_level=3"

# 获取完整路径
curl "http://www.cmspro.com/api/admin/cmspro/region/path?code=110101"

# 获取数据统计
curl "http://www.cmspro.com/api/admin/cmspro/region/stats"
```

### 3.9 导出全量数据快照包

后台「行政区划 → 数据管理」页面提供「**导出快照包**」按钮，将库中全量区划数据（含 status=0 禁用记录、含坐标）导出为标准化 ZIP 快照包，供上传至版本服务器（Versionsvr 应用「区划数据」服务）发布，各站点区划应用在线同步——使区划数据更新与区划应用发版解耦。

**操作流程**：

1. 确认库中数据为最新（可通过「一键数据更新」先更新）。
2. 点击「导出快照包」按钮，在弹窗中填写快照版本号（留空自动生成 `YYYYMMDD001` 格式）。
3. 点击「导出」，浏览器下载 `cmspro-region-data-{版本号}.zip`（内含 `regions.json` 全量记录 + `meta.json` 版本统计）。
4. 前往版本服务器后台「版本服务 → 区划数据」上传该 ZIP 发布。

**导出包契约**（与版本服务器校验规则对齐）：

| 文件 | 内容 |
|------|------|
| `regions.json` | 全量记录数组 `[{code, name, level, parent_code, status, lon, lat}, ...]`，按 level + code 排序（父级先于子级），顶级记录 `parent_code` 为 `'0'` |
| `meta.json` | `{version, count, stats: {province, city, district, street, village}, generated_at, format}` |

> 说明：库中须已有省级（level=1）数据才可导出；导出为全量快照（含禁用记录与无坐标记录，`lon`/`lat` 为 null）；版本号仅允许字母、数字、点、下划线、连字符，最长 32 位。

### 3.10 导入快照包（站点间分享）

后台「行政区划 → 数据管理」页面提供「**导入快照包**」按钮，与 3.9「导出快照包」配对——接收其他站点分享的 `cmspro-region-data-{版本号}.zip` 直接上传导入，**全量替换**本地区划数据，无需经过版本服务器，适合站点之间点对点分享数据集。

**操作流程**：

1. 从分享方获取快照包 ZIP（由对方站点「导出快照包」生成，或版本服务器下载的历史发布包，两者格式相同）。
2. 点击「导入快照包」按钮选择文件，确认弹窗提示「导入将全量替换本地区划数据（本地手工修改会被覆盖）」。
3. 点击「开始导入」，弹出与在线同步一致的**实时进度条弹层**（解包校验 25% → 契约校验 45% → 分层落库 48%~82% → 闭包表重建 84% → 清缓存记版本 90%~100%）。
4. 完成后页面自动刷新；已导入版本号取包内 `meta.json` 的 `version` 写入「已同步数据版本」配置项（包内无 meta.json 时回退记录 `snapshot-{导入时刻}`）。

**安全机制**（与在线同步一致，另无 SHA-256 校验——上传包无可信校验和来源，故须仅导入可信站点分享的包）：

| 防护 | 说明 |
|------|------|
| 上传校验 | 仅接受 zip 格式、最大 50MB |
| 契约前置校验 | 解包（防 Zip Slip）后按同一套契约规则校验（必填/code 唯一（≤12 位）/层级引用闭环/省级必含/上限 60 万），非法数据进事务前直接拒绝 |
| 事务包裹 | 落库全程单事务，任一步失败整体回滚，本地数据零影响 |

### 3.11 在线同步官方数据（推荐）

后台「行政区划 → 数据管理」页面提供「**在线同步官方数据**」按钮，从版本服务器（Versionsvr 应用「区划数据」服务）在线同步官方行政区划数据，**全量替换**本地数据——新装站点或数据陈旧的站点无需再跑「一键导入/一键数据更新」（约 1 小时），**点击一次即可完成初始化（预计 1 分钟内）**。

**操作流程**：

1. 点击「在线同步官方数据」按钮，系统自动检查版本服务器最新已发布数据版本；弹窗中「本地」位置展示当前已同步版本号（从未同步则为「未同步」）。
2. 有新版本时弹窗展示远端版本信息（版本号、发布时间、记录总数与五级统计、更新说明），并提示「同步将全量替换本地区划数据（本地手工修改会被覆盖）」。
3. 点击「开始同步」，弹出**实时进度条弹层**，按阶段推进：下载数据包（5%）→ SHA-256 校验（20%）→ 解包与契约校验（30%~45%）→ 分层批量落库（48%~82%，街道层按批次细分）→ 闭包表重建（84%）→ 清缓存记版本（90%~100%）。进度经 `sync-progress` 接口轮询（800ms/次），执行期间请勿关闭或刷新页面。
4. 完成后进度条到 100% 自动关闭，页面自动刷新，数据即为官方最新版本。

**安全机制**：

| 防护 | 说明 |
|------|------|
| 完整性校验 | 下载包 SHA-256 与版本服务器声明值比对，不符拒绝且本地数据零影响 |
| 契约前置校验 | 数据结构/字段/层级引用/省级必含校验在进事务前执行，非法数据直接拒绝 |
| 事务包裹 | 落库全程单事务，任一步失败整体回滚，本地数据零影响 |
| 版本回退 | 版本服务器保留历史版本下载，可指定旧版本号同步回退（接口 `version` 参数） |
| 重复保护 | 本地已是最新版本时跳过下载，避免重复同步 |

**性能基准**：

- 四级数据包（sqlite 内存库实测，49334 条四级区划 + 19.3 万条闭包记录）：契约校验 0.73s + 全量替换落库 5.11s ≈ **5.84s**；生产 MySQL 环境预计 1 分钟内完成（对比旧「一键导入」链路约 1 小时）。
- 五级村级数据包（MySQL 8 实测，584,265 条 + 284 万条闭包记录）：同步链路全程流式化（校验结果写 JSONL 中间产物、按层级分遍扫描批量落库、闭包表 `INSERT...SELECT` 逐层重建、缓存按版本号整体失效），512M 内存限制下**内存峰值仅 86MB**；流式校验约 3 分钟 + 插入 58 万条约 4 分钟 + 闭包重建约 1 分钟，五级全量同步耗时约 10 分钟量级，**建议低峰期执行**，执行期间请勿关闭或刷新页面。

**版本记录**：已同步版本号写入「数据同步设置 → 已同步数据版本」配置项（`app_cmspro_region_data_sync_version`，系统自动维护）。配置组由框架在应用安装/升级时按 manifest 落库；**若站点未执行过升级导致配置组缺失，同步时会自动创建该组**（`firstOrCreate` 自愈），确保版本号一定写入、前端「本地版本」正常显示，无需用户手动升级。

### 3.12 更新区划坐标（开发模式）

仅当 `.env` 中 `APP_DEV_MODE=true` 时，数据管理页「搜索」按钮右侧才显示「**更新坐标**」入口（生产环境不渲染，接口也会拒绝执行）。弹窗提供「单个更新」与「批量自动更新」两个页签。

#### 单个更新

1. 按 省/直辖市 → 市 → 区/县 → 街道/乡镇 逐级选择；任一级选中后均可作为更新目标（直辖市、省直辖县级市等层级不齐的情况会自动跳级）。
2. 系统按选中路径组装百度正地址解析地址，规则为「省+市」与「区县+街道」之间保留一个空格，例如 `浙江省嘉兴市 秀洲区嘉北街道`。
3. 选中任一级区划后，「百度请求地址」下方会实时回显该区划**当前库中的经纬度**（GCJ-02，查询 `GET /api/admin/cmspro/region/coordinate`，直连数据库不走缓存）：有坐标显示 `经度, 纬度`（绿色），无坐标显示红色「暂无经纬度」；切换级联时随之刷新，单个更新成功后立即回显最新值。
4. 点击「获取坐标并更新」，前端通过百度地图 JSAPI（`BMapGL.Geocoder.getPoint`）解析地址得到 BD-09 坐标，再调用本应用接口写库（`POST /api/admin/cmspro/region/update-coordinate`）。
5. 写库前自动将 BD-09 转换为 GCJ-02，与应用内其他坐标保持一致；执行结果会同时展示百度坐标与最终存储坐标。
6. 弹窗保留，可继续选择其他区划逐条更新；表格会自动刷新。

#### 批量自动更新

一次性补齐省/直辖市、市、区县、街道乡镇的经纬度，无需逐条选择。

1. 切换到「批量自动更新」页签，勾选需要更新的层级（默认四级全选）。
2. 「仅更新缺失坐标」默认勾选：只处理 `lon`/`lat` 为空的记录；取消勾选则对选中层级全部重新解析并覆盖。
3. 「请求频率」设置每秒请求数（QPS，取值 1~10，默认 3）：控制每秒最多发起多少条百度解析请求，数值越低越稳；任务运行中修改即时生效，未运行时修改会同步到断点任务。
4. 点击「开始更新」：前端按区划代码顺序分页拉取待更新列表（`GET /api/admin/cmspro/region/coordinate-candidates`，游标分页每页 100 条），3 并发逐条调用百度地理编码，并按 QPS 限制发起间隔（最小间隔 = 1000 / QPS 毫秒），解析结果每 20 条批量写库（`POST /api/admin/cmspro/region/update-coordinate-batch`）。
5. 进度条实时显示已处理/总数、成功、失败条数；日志区记录未解析到坐标或写库失败的条目（单条解析失败自动重试 2 次）。
6. 支持「暂停/继续」与「停止」；进度与请求频率一起保存在浏览器 localStorage，页面刷新或关闭后可点击「继续上次任务」从断点继续。断点游标仅在整页处理完成后推进，避免漏更新。
7. 完成后表格与统计卡片自动刷新。

| 层级 | 参考数据量 | 说明 |
|------|-----------|------|
| 省/直辖市 | 34 | 解析为省级行政中心点 |
| 市 | 300+ | |
| 区/县 | 3000+ | |
| 街道/乡镇 | 约 4 万 | 数据量大，需保持页面打开 |

> 批量更新受百度地图 JSAPI 并发与配额限制，街道级全量补齐可能持续数小时，建议先跑省/市/区县，再单独跑街道，或按需只勾选缺失层级。仅补缺失模式下已完成记录不会重复消耗配额。出现频繁失败或限流时，可把请求频率降到 1~2 次/秒。
>
> AK 复用「地图」应用中配置的**浏览器端 AK**（`baidu_js_ak`），需在百度地图开放平台为该 AK 配置当前域名 Referer 白名单；未配置 AK 时点击按钮会给出提示。坐标系转换复用「地图」应用的 `CoordinateConverter`，未安装「地图」应用时接口返回明确错误。

## 六、常见问题

### Q: 安装后没有数据？

安装应用仅创建数据库表，需在后台「行政区划 → 数据管理」页面手动点击「导入三级数据」导入。

### Q: 导入数据提示超时？

三级数据采用按省份分步导入策略，每个省份独立请求，不会超时。如仍异常，请检查服务器能否访问民政部 API。

### Q: 如何启用街道/乡镇四级数据？

在 CmsPro 后台「系统设置 → 区划设置」中开启「启用街道级数据」选项，然后在数据管理页面点击「导入街道数据」。

### Q: 如何获取行政村/社区五级数据？

村级/社区级（level=5，约 54 万条）数据通过「在线同步官方数据」获取：版本服务器 `20261107001` 及以后版本包含村级数据（村级为 12 位编码，应用升级时自动扩容 code 字段）。五级全量约 58 万条，同步耗时约 10 分钟量级（内存峰值远低于 512M 限制），建议低峰期执行。

### Q: 数据更新后前台不生效？

查询结果缓存 24 小时，数据更新时自动清除；如仍异常，可手动点击「清除缓存」。

### Q: 直辖市如何查询子级？

北京、天津、上海、重庆的区县直接挂在省级下（无中间市级），`getChildren('110000')` 直接返回区县列表。
